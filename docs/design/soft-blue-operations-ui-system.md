# 柔和蓝白运营后台 UI 系统

> 可复用版本：1.0
> 适用范围：运营后台、内部工具、分析工作台、项目管理台、审核系统、数据管理产品
> 核心气质：明亮、轻盈、可靠、友好、专业

## 1. 设计目标

这套 UI 系统把柔和的蓝白视觉语言应用到高频运营工具中。它追求的是“长时间使用仍然舒服”，而不是营销页面式的视觉表演。

设计必须同时满足：

- 页面第一眼明亮、清爽、有呼吸感。
- 重要数据可快速扫描，操作路径稳定。
- 数据密集页面不因大留白降低效率。
- 状态、风险和错误不能只靠颜色表达。
- 不依赖卡通吉祥物、花朵、云朵等装饰来制造亲和力。
- 组件可以跨页面、跨项目复用，而不是逐页写特殊样式。

## 2. 适用与不适用场景

适合：

- 日常运营和项目管理后台。
- 数据分析、任务调度和内容审核工作台。
- 面向非技术用户的内部系统。
- 需要同时容纳概览卡片、表格、筛选器和表单的产品。

谨慎使用：

- 需要极高信息密度的交易终端。
- 以深色监控大屏为主的系统。
- 强品牌营销站、娱乐产品或沉浸式内容站。

## 3. 核心原则

### 3.1 暖白打底，蓝色引导

背景不是冷灰，也不是纯白。使用轻微偏暖的白色降低长时间观看的疲劳；蓝色只负责选中、主操作、进度和关键数据。

### 3.2 边框塑形，阴影退后

卡片主要依靠细边框和背景层级区分。阴影只提供轻微浮起感，不能出现厚重、发灰的大面积投影。

### 3.3 概览舒展，工作台紧凑

同一产品允许两种密度：

- `comfortable`：总览、空状态、新建流程、低频设置。
- `compact`：表格、新闻列表、审核工作台、运行详情。

不要把参考图的大留白机械复制到数据密集页面。

### 3.4 语义色保持独立

蓝色是品牌与交互色，不替代状态色。成功使用绿色，警告使用琥珀色，错误使用红色，中立状态使用蓝灰色。

### 3.5 亲和力来自细节

圆角、线性图标、清晰文案、平滑反馈和舒适间距共同产生亲和感，不需要卡通装饰。

## 4. 设计令牌

### 4.1 字体

优先使用系统字体，保证中文显示稳定且离线可用。

```css
--font-sans: Inter, "SF Pro Display", "Segoe UI", "PingFang SC",
  "Microsoft YaHei", system-ui, sans-serif;
--font-mono: "SFMono-Regular", Consolas, "Liberation Mono", monospace;
```

字体层级：

| 用途 | 字号 | 行高 | 字重 |
|---|---:|---:|---:|
| 页面主标题 | 32px | 1.2 | 700 |
| 区块标题 | 20px | 1.3 | 650 |
| 卡片标题 | 16px | 1.4 | 650 |
| 正文 | 14px | 1.65 | 400 |
| 辅助信息 | 12px | 1.5 | 400 |
| 指标数字 | 30–36px | 1.1 | 700 |

中文标题避免过度放大。数据页面主标题可降至 28px，窄屏降至 24px。

### 4.2 颜色

```css
:root {
  --ui-bg: #f8fafc;
  --ui-bg-warm: #fbfaf7;
  --ui-surface: #ffffff;
  --ui-surface-soft: #f7faff;
  --ui-surface-blue: #edf5ff;

  --ui-text: #101828;
  --ui-text-secondary: #475467;
  --ui-text-muted: #667085;
  --ui-text-disabled: #98a2b3;

  --ui-primary: #1769f6;
  --ui-primary-hover: #0f5de0;
  --ui-primary-active: #0b4fc1;
  --ui-primary-soft: #eaf2ff;
  --ui-primary-border: #bdd4ff;

  --ui-border: #d9e2ef;
  --ui-border-soft: #e8edf4;
  --ui-focus: #84adff;

  --ui-success: #168554;
  --ui-success-soft: #eaf8f1;
  --ui-warning: #a15c00;
  --ui-warning-soft: #fff7e6;
  --ui-danger: #c4322b;
  --ui-danger-soft: #fff0ee;
  --ui-neutral-soft: #f2f4f7;
}
```

对比要求：

- 正文与背景对比度至少达到 WCAG AA。
- 浅蓝背景上的文字使用深蓝或深灰，不使用浅蓝文字。
- 状态标签同时显示文字或图标，不单独使用色点。

### 4.3 间距

使用 4px 基础网格：

```css
--space-1: 4px;
--space-2: 8px;
--space-3: 12px;
--space-4: 16px;
--space-5: 20px;
--space-6: 24px;
--space-8: 32px;
--space-10: 40px;
--space-12: 48px;
```

建议：

- 页面区块间距：24–32px。
- 舒展卡片内边距：24px。
- 紧凑卡片内边距：16–20px。
- 表格单元格垂直内边距：12–14px。
- 表单字段间距：16px。

### 4.4 圆角、边框与阴影

```css
--radius-sm: 8px;
--radius-md: 12px;
--radius-lg: 18px;
--radius-xl: 22px;
--radius-pill: 999px;

--shadow-card: 0 8px 28px rgb(31 64 120 / 0.06);
--shadow-float: 0 18px 48px rgb(31 64 120 / 0.12);
```

- 普通卡片：1px 边框、18px 圆角、可选轻阴影。
- 弹窗和浮层：22px 圆角、`--shadow-float`。
- 输入框和按钮：10–12px 圆角。
- 不使用连续三层以上的嵌套圆角卡片。

### 4.5 图标

- 使用 1.75–2px 描边的线性图标。
- 常规尺寸 18–20px，指标卡图标 22–24px。
- 图标必须与文字标签共同出现，只有行业通用操作可单独使用。
- 不混用填充图标、Emoji 和不同风格的 SVG。

## 5. 应用外壳

### 5.1 侧边栏

- 桌面宽度 232–248px。
- 暖白或纯白背景，与主内容使用细边框分隔。
- 品牌区高度 72–88px。
- 导航项高度 44–48px，圆角 12px。
- 选中项：浅蓝背景、蓝色图标和文字。
- 未选中项：深灰文字；悬停时出现轻微蓝灰背景。
- 导航分组之间使用 20–28px 间距，不滥用分隔线。

### 5.2 顶部栏

- 高度 60–68px。
- 只放页面上下文、全局状态和必要操作。
- 不重复显示侧边栏已经表达的完整品牌信息。
- 滚动时可保持粘性，但阴影必须非常轻。

### 5.3 主内容区

- 桌面最大宽度建议 1440–1520px。
- 左右安全间距 28–40px。
- 小屏安全间距 16px。
- 页面标题与第一块内容之间保留 24px。

## 6. 页面模板

### 6.1 运营总览

推荐结构：

1. 问候或页面标题区。
2. 主要趋势、任务或运行状态区域。
3. 2×2 或 4 列指标卡。
4. 最近记录与系统检查双栏。

首页允许更多留白和更大的指标数字，但每张卡只表达一个主要结论。

### 6.2 数据详情页

推荐结构：

1. 标题、时间与主要操作。
2. 4–6 项紧凑摘要带。
3. 横向阶段时间线。
4. 数据获取或质量摘要。
5. 标签页工作区。
6. 表格、列表或证据卡。

摘要带可以是连续分栏容器，不需要把每个指标都做成独立悬浮卡片。

### 6.3 审核工作台

桌面采用三栏：

- 左：审核队列，260–300px。
- 中：正文阅读和编辑，自适应宽度。
- 右：证据、治理和操作，320–380px。

栏之间使用 16–20px 间距。中栏必须获得最大阅读宽度。窄屏改为队列、正文、证据纵向排列。

### 6.4 表单流程

- 步骤数量不超过 5 个。
- 每一步只包含同一决策主题。
- 主操作放右侧，返回或取消放左侧。
- 提交前展示清晰摘要和成本、权限或数据影响。

## 7. 组件规范

### 7.1 卡片

卡片必须有明确职责：指标、内容、操作或状态。禁止为了视觉层次把每一行都包成卡片。

指标卡结构：图标、标签、主数值、补充说明、可选进度条。主数值是视觉焦点，图标背景使用浅蓝而非高饱和蓝块。

### 7.2 按钮

- 主按钮：蓝底白字，每个区域最多一个。
- 次按钮：白底蓝灰边框。
- 幽灵按钮：透明背景，用于低优先级操作。
- 危险按钮：红色，仅用于不可逆或高风险操作。
- 高度 38–42px，触控场景至少 44px。
- 禁用状态必须同时降低对比度并禁止交互。

### 7.3 输入框与选择器

- 默认白底，1px 蓝灰边框。
- 聚焦时显示 2–3px 半透明蓝色焦点环。
- 标签始终可见，不用 placeholder 替代字段名称。
- 错误信息放在字段下方，说明原因和修复方法。

### 7.4 标签页与分段控制

- 页面级标签页使用独立按钮组，选中项蓝底白字或浅蓝底蓝字。
- 小范围二选一使用分段控制。
- 标签文字简短，避免一项超过 8 个中文字符。
- 键盘焦点顺序必须与视觉顺序一致。

### 7.5 状态标签

- 使用胶囊形状，字号 12px。
- 包含中文状态名称；内部错误码另行显示。
- 成功、进行中、等待、警告、失败应有稳定映射。

### 7.6 表格

- 表头使用 12px 中等字重和柔和灰色。
- 行高 48–56px，数据密集模式可降至 44px。
- 只使用横向分隔线，避免完整网格围栏。
- 数字右对齐；名称和说明左对齐。
- 长 ID 使用等宽字体并截断，悬停或复制时可查看完整值。
- 小屏优先横向滚动；只有列数较少时才转换成卡片列表。

### 7.7 空状态、加载与错误

- 空状态说明“为什么为空”和“下一步做什么”。
- 加载状态尽量保留页面骨架，避免整页闪烁。
- 错误卡使用浅红背景和清晰标题，提供重试入口。
- 长任务显示阶段、最近更新时间和是否自动刷新。

### 7.8 弹窗

- 只用于需要明确中断当前流程的决定。
- 标题描述动作，正文说明后果。
- 默认焦点放在取消按钮或最安全操作上。
- 支持 Escape、焦点回收和键盘操作。

## 8. 数据可视化

- 主折线使用 `--ui-primary`，辅助线使用低饱和蓝灰。
- 网格线细且淡，避免形成表格感。
- 趋势图只强调最后一个值或异常点。
- 同一图表尽量不超过 5 种颜色。
- 涨跌语义应遵循目标市场习惯，但必须提供符号或文字辅助。

## 9. 动效

- 常规过渡：140–180ms。
- 弹窗与侧栏：180–240ms。
- 使用 `ease-out` 进入、`ease-in` 离开。
- 只动画 `opacity` 和 `transform`，避免大面积布局抖动。
- 遵循 `prefers-reduced-motion`。

## 10. 响应式

建议断点：

- `>= 1280px`：完整侧边栏，多列布局。
- `960–1279px`：缩减边距，指标卡 2 列。
- `720–959px`：侧边栏收起，工作台纵向。
- `< 720px`：单列布局，按钮可全宽，表格横向滚动。

不要单纯按设备名称设计；以内容开始拥挤的宽度为准调整断点。

## 11. 可访问性

- 所有交互元素必须具有可见焦点。
- 图标按钮必须有 `aria-label`。
- 标签页使用正确的 `tablist`、`tab`、`tabpanel` 语义。
- 状态更新使用适当的 `aria-live`，避免频繁打断屏幕阅读器。
- 弹窗管理焦点并支持 Escape。
- 颜色不是唯一信息载体。
- 点击目标不小于 40×40px，移动端不小于 44×44px。

## 12. 文案风格

- 使用动作明确、自然的中文。
- 按钮写“新建分析”“重新加载”，不写模糊的“确定”“处理”。
- 错误信息包含对象、原因和下一步。
- 专业术语首次出现时提供中文解释，内部状态码放在辅助信息中。
- 空状态不责怪用户，不写“你还没有……”。

## 13. 禁止模式

- 禁止在每个区块都使用大阴影。
- 禁止卡片套卡片再套卡片。
- 禁止整页使用纯白背景而没有层级。
- 禁止为了接近参考图而给数据表加入过大行距。
- 禁止在一个区域放多个同等醒目的主按钮。
- 禁止用 Emoji 代替正式图标。
- 禁止用低对比浅蓝文字承载正文。
- 禁止无意义渐变、玻璃拟态和持续循环动画。
- 禁止隐藏标签，只依赖 placeholder。

## 15. 复用流程

在新项目中按以下顺序落地：

1. 复制设计令牌，不先复制页面级 CSS。
2. 建立按钮、表单、卡片、状态、标签页、表格六类基础组件。
3. 完成应用外壳和一张代表性数据页。
4. 检查舒展与紧凑两种密度是否成立。
5. 再扩展其他页面，避免逐页产生新视觉规则。
6. 用桌面和窄屏各验收一次。
7. 运行自动化测试、生产构建和可访问性检查。

## 16. 完成检查清单

- [ ] 页面背景、表面和边框层级清楚。
- [ ] 主色只用于关键交互与强调。
- [ ] 总览舒展，数据页紧凑。
- [ ] 状态色和文案映射一致。
- [ ] 所有表单标签与焦点状态可见。
- [ ] 表格在窄屏可用。
- [ ] 空、加载、错误、禁用状态完整。
- [ ] 无卡片过度嵌套、厚重阴影或无意义装饰。
- [ ] 键盘可以完成关键流程。
- [ ] 动效遵循减少动态偏好。
- [ ] 自动化测试与生产构建通过。
