## 2. 不可违反的产品原则

### 2.1 真实能力优先

- 没有真实数据的指标不得用静态数字填充。
- 没有行为实现的控件不得做成可点击按钮。
- 没有业务价值的参考图功能不得为了视觉相似而加入。
- 页面需要的新能力应按业务价值增量补充后端，而不是在前端伪造。
- 缺失、未知和未配置必须显式表达，不能默认为零或正常。

### 2.2 一套产品外壳

全站使用同一套侧边栏、顶部栏、页面标题区、反馈方式和响应式规则。页面之间可以改变内容密度和工作区结构，但不能为每张参考图制造独立导航。

### 2.3 概览舒展，工作台紧凑

- 运营总览使用 `comfortable` 密度，强调扫描与决策。
- 数据运行、列表和管理页面使用 `compact` 密度，强调效率。
- 审核工作台使用 `workspace` 密度，强调连续编辑和多栏协作。

### 2.4 结构化业务不可因视觉重构退化

审核草稿继续保留标题、导语、正文分节、结论、风险提示、字段版本、哈希和证据锚点。视觉上可以接近连续文档，但不能改成无法治理的任意富文本。

## 3. 视觉语汇

目标气质：明亮、清晰、可信、克制、适合长时间运营使用。

- 背景：微冷的浅蓝灰，不用纯灰和大面积纯白。
- 表面：白色为主，极浅蓝用于选中、强调和局部层级。
- 品牌色：清透蓝，只用于主操作、选中、进度和关键数据。
- 结构：细描边、适度圆角、极轻阴影。
- 字体：中文系统字体优先，数字和英文保持清晰。
- 图标：统一线性 SVG，禁止 Emoji 和多套图标混用。
- 装饰：不加入卡通人物、云朵、花草或无业务意义插画。


所有正文必须满足 WCAG AA 对比度。状态必须同时使用文字或图标，不得只依赖颜色。

### 4.2 字体

```css
--sp-font-sans: Inter, "Segoe UI", "PingFang SC", "Microsoft YaHei",
  system-ui, sans-serif;
--sp-font-mono: "SFMono-Regular", Consolas, "Liberation Mono", monospace;
```

| 层级 | 字号 | 行高 | 字重 |
|---|---:|---:|---:|
| 页面标题 | 30–32px | 1.2 | 700–760 |
| 工作台标题 | 26–28px | 1.25 | 700 |
| 区块标题 | 16–18px | 1.4 | 650–720 |
| 卡片标题 | 14–16px | 1.4 | 600–680 |
| 正文 | 14px | 1.6 | 400 |
| 辅助信息 | 12px | 1.5 | 400–500 |
| 指标数字 | 28–34px | 1.05 | 720–780 |

技术 ID 使用等宽字体，默认截断但允许复制完整值。

### 4.3 间距

使用 4px 基础网格：

```css
--sp-space-1: 4px;
--sp-space-2: 8px;
--sp-space-3: 12px;
--sp-space-4: 16px;
--sp-space-5: 20px;
--sp-space-6: 24px;
--sp-space-8: 32px;
--sp-space-10: 40px;
--sp-space-12: 48px;
```

- 页面区块间距：18–24px。
- 页面水平安全间距：桌面 26–40px，移动端 16px。
- 舒展面板内边距：20–24px。
- 紧凑面板内边距：14–18px。
- 表格行高：44–52px。
- 表单字段间距：14–18px。

### 4.4 圆角、边框和阴影

```css
--sp-radius-sm: 8px;
--sp-radius-md: 10px;
--sp-radius-lg: 16px;
--sp-radius-xl: 20px;
--sp-radius-pill: 999px;

--sp-shadow-card: 0 10px 30px rgb(35 72 126 / 0.07);
--sp-shadow-float: 0 18px 48px rgb(35 72 126 / 0.13);
```

- 普通面板：1px 边框、16px 圆角、可选轻阴影。
- 表格和连续工作区优先使用边框，不滥用阴影。
- 浮层、抽屉和对话框才使用更明显阴影。
- 禁止连续三层以上圆角卡片嵌套。

### 4.5 动效

- 常规反馈：140–180ms。
- 抽屉与对话框：180–240ms。
- 只动画 `opacity`、`transform` 和少量颜色。
- 不使用持续循环装饰动画。
- 完整支持 `prefers-reduced-motion`。

## 5. 应用外壳

### 5.1 桌面布局

- 完整侧边栏宽度：224–236px。
- 顶部栏高度：64–68px。
- 侧边栏固定，顶部栏粘性固定。
- 只有右侧主内容区承担页面级滚动。
- Dashboard 内容最大宽度约 1360–1420px。
- Workbench 内容最大宽度约 1480–1520px。
- Review Workspace 使用可用全宽。

### 5.2 统一导航

```text
SectorPulse
智能板块研判平台

运营
├─ 运营总览
├─ 分析运行
└─ 审核工作台

管理
├─ 定时任务
├─ 系统状态
└─ 影子验收
```

- “新建分析”属于页面主操作，不单独占导航。
- 数据运行详情和内容运行详情属于二级路由，不出现在侧边栏。
- 选中项使用浅蓝背景、蓝色文字与左侧强调线。
- 侧边栏底部只显示真实环境和版本信息，不伪造用户账号。

### 5.3 顶部栏

- 左侧显示当前位置或面包屑。
- 右侧可显示数据库、实时数据和 LLM 的真实综合状态。
- 页面级主操作放在内容标题区。
- 不加入无实际功能的搜索、通知或个人中心。

### 5.4 页面标题区

统一顺序：页面名称、说明、可选上下文、次操作、主操作。一个标题区最多一个主按钮和两个次按钮。

## 6. 三类页面模板

### 6.1 DashboardLayout

适用于运营总览：固定最大宽度、舒展指标区、趋势与状态双栏、紧凑近期记录。

### 6.2 WorkbenchLayout

适用于数据运行、内容运行、定时任务和系统状态：宽内容区、紧凑摘要带、阶段进度、页签、表格和抽屉。

### 6.3 ReviewWorkspaceLayout

适用于审核工作台：全宽三栏，高度占满顶部栏以下区域，各栏独立滚动，审批操作保持可见。

## 7. 核心页面布局

### 7.1 运营总览

```text
页面标题与操作
├─ 4 张核心指标卡
├─ 运行趋势（约 2/3）+ 系统就绪状态（约 1/3）
└─ 最近运行表格
```

指标建议：运行总数、今日已完成、运行中、异常与待处理。趋势和变化值只能来自 PostgreSQL 聚合。

### 7.2 数据运行工作台

```text
运行标题与操作
├─ 运行摘要带
├─ 阶段进度
├─ 数据获取概览与来源状态
├─ 候选板块选择工作区
└─ 行情 / 新闻 / 证据 / 质量页签
```

- 已完成阶段可折叠为摘要。
- 候选板块选择必须持久化。
- 未确认选择前禁用草稿生成，并说明原因。
- 新闻详情区分完整正文、摘要和快讯。
- 主要操作可以使用底部吸附操作栏。

### 7.3 审核工作台

```text
审核队列 22% | 草稿编辑区 53% | 证据与决策 25%
```

- 左栏最小约 260px。
- 中栏正文有效阅读宽度约 680–820px。
- 右栏约 320–380px。
- 草稿视觉为连续稿纸，但数据仍为结构化字段。
- 右栏分为来源、证据判定、治理记录。
- 批准与退回操作固定在右栏底部。

## 8. 组件规范

### 8.1 指标卡

结构为图标、名称、主数值、解释或派生指标。每张卡只表达一个结论；数字是视觉焦点，图标不得压过数字。

### 8.2 按钮

- 主按钮：蓝底白字，每个区域最多一个。
- 次按钮：白底蓝灰边框。
- 幽灵按钮：用于低优先级动作。
- 危险按钮：只用于不可逆或高风险动作。
- 桌面高度 38–42px，移动端至少 44px。
- 加载时保持原宽度，防止布局跳动。

### 8.3 状态标签

使用稳定语义映射：成功绿色、运行中蓝色或琥珀色、等待蓝灰、警告琥珀、失败红色。内部错误码放在辅助详情，不替代中文状态。

### 8.4 数据表格

- 表头轻量，主体仅保留横向分隔线。
- 重要列固定可见，低优先级信息进入详情抽屉。
- 数字右对齐，文字左对齐。
- 支持分页、排序、筛选、加载和空状态。
- 移动端优先保留任务所需字段，不盲目把每行转为巨大卡片。

### 8.5 页签和分段控制

- 页面数据域使用页签。
- 近 7 天/30 天等同一维度切换使用分段控制。
- 具备正确 ARIA 语义、键盘切换和可见焦点。

### 8.6 表单与编辑器

- 标签始终可见，不用 placeholder 代替标签。
- 聚焦显示 2–3px 半透明蓝色焦点环。
- 错误信息包含原因和修复方式。
- 审核编辑区在未聚焦时弱化输入框边界，形成连续文档观感。
- 自动保存必须显示保存中、已保存、失败、冲突四类状态。

### 8.7 抽屉和对话框

- 行详情、新闻详情和编辑表单优先使用右侧抽屉。
- 需要中断流程的确认才使用对话框。
- 支持 Escape、焦点锁定和关闭后的焦点恢复。
- 破坏性操作默认焦点放在取消按钮。

### 8.8 页面状态

每个页面必须覆盖：加载、空数据、局部失败、整页失败、禁用、保存冲突和操作成功。错误文案回答“发生了什么、已有数据是否保留、下一步是什么”。

## 9. 数据真实性规则

- 指标必须说明计算范围和更新时间。
- 无法计算时显示“暂无数据”或“未知”，不显示 `0`。
- 新闻必须区分标题、摘要、正文、原文 URL 和来源。
- 外部来源链接不存在时不展示“查看原文”。
- Provider、LLM 和数据库只显示就绪状态，绝不显示密钥和连接密码。
- 示例原型必须显式标注“示意值”。正式页面不得保留示意数据。

## 10. 响应式规则

| 视口 | 规则 |
|---|---|
| `>= 1280px` | 完整侧边栏，多列布局，三栏审核工作区 |
| `1024–1279px` | 缩窄侧边栏，减少安全间距，指标两列或四列自适应 |
| `768–1023px` | 侧边栏抽屉，复杂工作区转换为页签或主次双栏 |
| `< 768px` | 单列主内容，44px 触控目标，表格按任务保留关键列 |

审核工作台在窄屏切换为“队列 / 草稿 / 证据”三个页签，不能把三栏压缩成不可读窄列。

## 11. CSS 与代码组织

```text
web/src/styles/
├─ tokens.css
├─ base.css
├─ shell.css
├─ components/
├─ patterns/
├─ pages/
└─ responsive.css
```

- 使用 CSS cascade layers 明确基础、组件、模式和页面覆盖顺序。
- 保持 React、TypeScript 和语义 CSS，不引入 Tailwind 或大型 UI 框架。
- 页面组件不得继续向单一全局 CSS 文件无限追加规则。
- 业务复杂组件留在模块内部，真正跨页面的视觉组件才进入通用组件库。

## 12. 无障碍与国际化

- 所有交互元素有可见焦点。
- 图标按钮有可访问名称。
- 对话框、标签页、状态更新和表格使用正确语义。
- 页面支持键盘完成新建分析、候选选择、草稿修改和审核。
- 中文文案不依赖固定字符宽度，英文 Provider、错误码和长 ID 可安全换行或截断。
- 时间统一显示时区，API 保存标准时间。

## 13. 禁止模式

- 禁止假按钮、假指标、假通知和假用户资料。
- 禁止为了“像参考图”加入无关业务模块。
- 禁止大面积渐变、玻璃拟态、厚重阴影和持续动效。
- 禁止卡片套卡片再套卡片。
- 禁止多个同等醒目的主按钮。
- 禁止页面级滚动与多个无必要内层长滚动同时存在。
- 禁止审核正文被左右栏挤压到不可读宽度。
- 禁止只换颜色而不修复信息架构和密度。

## 14. 视觉验收矩阵

桌面高保真基准：

- 1536 × 1024
- 1440 × 900

响应式检查：

- 1280 × 800
- 1024 × 768
- 768 × 1024
- 390 × 844

每阶段至少检查：导航与滚动、标题层级、内容密度、空/加载/错误状态、键盘焦点、溢出和真实数据绑定。
