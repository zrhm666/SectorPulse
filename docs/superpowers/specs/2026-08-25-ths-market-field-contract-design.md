# 同花顺行情字段契约修正设计

## 1. 目标

修正同花顺备用行情 Provider 的接口选择和降级语义，确保：

- 行业板块展示同花顺真实返回的行情字段；
- 概念板块只有清单数据时明确标记为“仅板块清单”；
- 缺失行情指标不再被当作真实的零值参与候选排序；
- 东方财富继续作为行业、概念完整行情的首选来源；
- 页面继续区分“未返回”和真实数值 `0`。

## 2. 已验证的第三方字段契约

本项目当前安装 AKShare `1.18.87`。2026-08-25 的真实接口探测结果如下。

| AKShare 接口 | 返回数量 | 实际字段 | 用途 |
|---|---:|---|---|
| `stock_board_industry_name_ths` | 90 | `name`, `code` | 同花顺行业代码清单 |
| `stock_board_industry_summary_ths` | 90 | 序号、板块、涨跌幅、总成交量、总成交额、净流入、上涨家数、下跌家数、均价、领涨股、领涨股-最新价、领涨股-涨跌幅 | 同花顺行业行情概况 |
| `stock_board_concept_name_ths` | 375 | `name`, `code` | 同花顺概念代码清单 |
| `stock_board_concept_summary_ths` | 50 | 日期、概念名称、驱动事件、龙头股、成分股数量 | 概念时间表，不是实时行情 |
| `stock_board_industry_name_em` | 动态 | 板块代码、板块名称、涨跌幅、总市值、换手率、上涨/下跌家数、领涨股票、领涨股票涨跌幅等 | 东方财富行业完整行情 |
| `stock_board_concept_name_em` | 动态 | 板块代码、板块名称、涨跌幅、总市值、换手率、上涨/下跌家数、领涨股票、领涨股票涨跌幅等 | 东方财富概念完整行情 |

当前 `PandasThsAkShareClient` 错误地把两个 `*_name_ths` 清单接口当作完整行情接口，因此数据库中只有代码和名称，其余字段确实不存在。

## 3. 方案比较

### 方案 A：同花顺行业补全，概念诚实降级（采用）

- 行业同时请求名称清单和行业概况，按规范化板块名称合并；
- 概念继续请求名称清单，但标记为清单数据，不参与行情排序；
- 东方财富成功时仍使用完整行业、概念行情；
- 缺失字段通过 `available_fields` 表达，不伪造零值。

优点是请求数量固定、耗时可控、字段语义真实。缺点是东方财富失败时，同花顺不能提供完整概念行情。

### 方案 B：逐个概念请求历史指数

为每个概念调用 `stock_board_concept_index_ths`，计算最新涨跌幅。375 个概念会产生大量串行或并发请求，仍缺少换手率、涨跌家数和领涨股，且容易触发限流，不采用。

### 方案 C：把概念时间表映射为行情

将驱动事件、龙头股和成分股数量映射为当前行情字段。字段语义不一致，会制造错误数据，不采用。

## 4. 后端设计

### 4.1 同花顺行业合并

`PandasThsAkShareClient.fetch(INDUSTRY)` 并行或顺序调用：

1. `stock_board_industry_name_ths()` 获取 `name/code`；
2. `stock_board_industry_summary_ths()` 获取行业概况；
3. 对名称执行去首尾空白的精确匹配；
4. 以名称清单为主表合并概况字段；
5. 将 `板块` 规范化为 mapper 可识别的 `name`，将 `领涨股` 映射为 `leader_name`；
6. 保留原始供应商字段，使 `available_fields` 根据真实列名计算。

预期可用领域字段：

- `provider_sector_id`
- `name`
- `pct_change`
- `advancers`
- `decliners`
- `leader_name`
- `leader_pct_change`

`turnover_rate` 和 `total_market_cap` 仍不可用。

若概况接口失败，或名称清单与概况未能全量匹配，则整个行业 fallback 返回失败，不退回只有清单的“成功行情”，避免批次级 `available_fields` 把少量未匹配行误报为具备行情字段。

### 4.2 同花顺概念降级

`PandasThsAkShareClient.fetch(CONCEPT)` 继续返回概念代码和名称，但快照字段覆盖仅包含 `provider_sector_id/name`。该快照可用于展示分类清单和新闻关键词，不可作为行情排名输入。

### 4.3 候选排序资格

候选排序按每个快照的 `available_fields` 判断是否具备最低行情字段。最低要求为：

- 必须有 `pct_change`；
- 换手率、宽度等可选指标只有在 Provider 实际返回时才加入评分；
- 不可用指标不参与权重，也不作为零值进入归一化；
- 若一个分类快照缺少 `pct_change`，整个分类跳过行情候选排序；
- 新闻加分只应用于已经具有行情资格的板块，不允许仅靠新闻把清单记录变成行情候选。

当可用评分维度减少时，对剩余维度的权重重新归一化，保证评分仍位于可解释范围内。

### 4.4 数据质量语义

同花顺行业部分字段可用时保持成功状态，并由 `available_fields` 描述覆盖范围。同花顺概念只有清单字段时，采集可以成功，但质量报告和页面必须显示“仅板块清单，不参与行情排序”。这不是 Provider 请求失败，也不应显示为完整行情成功。

## 5. 前端设计

行情板块页增加来源能力提示：

- 完整行情：显示“完整行情字段”；
- 同花顺行业：显示“部分行情字段”，并列出未返回的总市值和换手率；
- 同花顺概念：显示“仅板块清单，不参与行情排序”；
- 表格仍使用 `available_fields` 判断“未返回”，不根据数值是否为零判断。

不新增图表，不伪造空字段，不为概念时间表展示行情标签。

## 6. 错误处理

- 行业名称接口或概况接口任一失败，返回可重试的 Provider 失败；
- 合并结果不是全量匹配时返回明确的字段契约错误，不产生部分成功快照；
- 不在 API 或 UI 暴露代理地址、请求头和第三方完整异常文本。

## 7. 测试与验收

- 客户端测试覆盖行业两接口合并和概念清单契约；
- mapper 测试覆盖 `领涨股` 别名以及缺失字段；
- 候选排序测试覆盖清单快照被跳过、部分指标动态加权和真实零值；
- 查询/API 测试覆盖能力标签；
- 前端测试覆盖“部分行情字段”和“仅板块清单”；
- 后端非 live 回归、Ruff、前端测试和生产构建通过；
- 最后使用真实同花顺接口验证行业返回 90 条且至少包含涨跌幅、上涨/下跌家数和领涨股，概念明确只返回清单字段。

## 8. 非目标

- 不增加新的行情 Provider；
- 不逐个抓取全部概念历史指数；
- 不把概念时间表当作实时行情；
- 不修改数据库迁移结构；
- 不触发真实 LLM。
