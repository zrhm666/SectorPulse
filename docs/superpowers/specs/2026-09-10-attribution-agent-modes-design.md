# 双模式归因设计

2026-09-10：用户确认双模式方向，并授权先完成设计、计划，再分阶段执行。界面统一使用“工作流模式”和“Agent 模式”。

## 目标与范围

保留简单归因 LLM 工作流，新增可自主选择工具并根据结果继续查证的归因 Agent。只替换归因环节；编辑、大纲、写作、审核、修订和人工批准沿用现有流程。

## 当前代码事实

- `Phase1BRequest` 尚无归因模式；`run_attribution_agents` 按板块执行一次结构化 LLM 请求。
- `LLMPort` 仅提供结构化生成接口，没有原生 tool_calls 协议。
- 已有 `KeywordNewsSearchPort`、新闻规范化/去重/证据门禁，以及按运行读取行情快照的仓库接口。
- `NewsDocument` 明确只承载元数据，summary 最多 500 字；当前没有正文详情读取 Port。
- 数据运行生成接口已要求确认候选板块；当前请求体未用于选择执行模式。

## 方案选择

推荐结构化工具决策循环：模型每轮选择调用工具或完成归因，程序验证请求、执行工具、记录观察结果，再交回模型。工具使用是否继续和参数由模型决定，程序控制权限和资源上限。复用当前 prompt JSON 约束及服务端校验，不要求供应商支持原生 function calling。

可选方案：扩展模型适配器实现原生 tool_calls，协议更标准但供应商兼容性需验证；引入完整 Agent 框架则增加依赖和持久化适配成本。本次不采用后二者，不妨碍以后增加适配器。

## 用户操作与模式传播

- 在确认候选板块后、点击生成分析稿前选择“简单归因”或“Agent 深度查证”。默认简单归因。
- 简单归因使用已采集证据，耗时较短；Agent 模式可追加检索、读取详情和核对行情，耗时及费用更高。
- 模式写入内容运行输入快照，列表与详情可查看；重试继承原模式。执行中的运行不能切换模式。
- 旧请求和旧数据缺失模式时按简单归因处理。直接创建内容运行和定时生成入口也必须有相同默认及模式传播规则。
- 模式与真实/Fixture Provider 相互独立。Fixture 为可重复的工具循环演练，不能展示成真实检索。

## Agent 循环

1. 接收可信板块名称、锁定行情快照、原始证据、数据截止时间及剩余资源。
2. 模型输出一个严格校验的动作：调用工具，或提交最终分析卡片。
3. 程序校验工具名称、参数、板块范围、截止时间和预算，然后执行工具。
4. 保存工具请求及观察结果，将结果追加到受限上下文，再由模型决定下一步。
5. 最终分析卡片通过证据 ID、可信名称、归因强度等校验后，交回既有写作流程。

每轮最多一个工具调用。记录简短查证目的和可见结果，不要求或保存模型隐含思维链。模型可以根据已有充分证据直接结束，无需强制走完所有工具。

## 首期工具

| 工具 | 输入与行为 | 输出 |
| --- | --- | --- |
| search_news | 当前板块相关关键词；时间范围由程序限制，复用启用的新闻搜索 Provider | 已登记文档 ID、标题、摘要、发布时间和来源 |
| read_news_detail | 已检索或已保存的文档 ID；读取已缓存详情或受支持来源的公开原文 | 正文/摘要、可用性、发布时间、读取时间、截断标记和内容哈希 |
| inspect_market | 当前运行中已确认候选板块的 ID 和类型；读取锁定快照并计算可解释的对照指标 | 实际存在的涨跌幅、上涨广度、领涨股等，以及缺失字段 |

正文读取新增独立 Port 与详情模型，不能将短摘要标成完整正文。不承诺支持任意新闻站点；首期选取项目实际来源中经验证可公开读取的站点适配，其他明确返回不可用。禁止任意 URL 输入，受控 URL 的跳转与解析也需检查内网地址、超时、响应大小及内容类型。

## 证据一致性与时间边界

新增检索结果必须经过现有规范化、去重、板块映射和时间检查，再形成归属于本内容运行的补充证据。模型不能自行提高来源等级或创建可引用证据 ID。

保存原始证据与新增证据的来源关系；按有效补充证据重新计算归因门禁，再验证最终卡片。合格新增来源必须传播到后续写作及审核，否则无法形成有效查证闭环。

行情始终使用本次运行锁定的快照，禁止把今天的实时行情当作历史运行行情。运行截止时间之后发布/观察到的内容按现有规则排除；后来读取的可变网页不能仅凭旧发布时间视为当时已知全文。严格历史模式缺少截止前可验证快照时，该正文只作补充背景并标注读取时间，不能抬高历史因果证据等级。

## 有界执行与退出

建议初始配置：每板块最多 6 次决策、5 次工具调用，单板块总时限 180 秒，最多 2 个板块并发。均允许后端配置。

共享整次运行预算，纳入 Agent 模型请求和后续写作阶段；并发任务需要原子预算预留，不能只在全部归因结束后检查。价格缺失时显示费用未知，不能以 0 元视为无成本；仍强制执行请求数、Token 及时间限制。

工具失败作为观察结果返回，允许模型在剩余额度内换关键词或结束；重复等价请求使用缓存并限制无进展循环。模型响应格式错误、工具越权、时间/预算耗尽、取消均有明确退出原因。无法得出可靠结论时保留可信证据并输出保守结论，不把失败标记为查证成功。

## 持久化与恢复

SQLite/PostgreSQL 同步支持 Agent 执行记录、步骤、工具结果引用和补充证据。记录 run_id、板块类型/ID、attempt、步骤序号、动作、状态、停止原因、耗时、用量与配置版本。

步骤写入采用稳定标识与幂等约束。服务中断保留轨迹并标记中断；首期人工重试创建新 attempt，复用可验证的已保存结果，不承诺透明自动恢复模型的中间决策。检索结果仍须满足原截止时间规则。

## 前端展示

沿用全站设计规范。模式选择放在生成动作附近；Agent 运行详情按板块显示检索次数、正在执行的工具、已找到的来源、正文是否可读及停止原因。提供可展开的查证轨迹；运行结束或刷新后从持久化接口恢复。

## 分阶段实施与验收

1. 模式字段、兼容默认、请求传播及隔离执行目录；验证旧接口、两种数据库和重试继承。
2. 新闻详情与受控工具，复用检索和行情快照；验证真实来源适配、摘要降级、时间边界和错误处理。
3. Agent 决策循环、共享预算、步骤持久化和补充证据回流；Fixture 验证工具顺序由模型决定、读结果后继续决策、提前结束及有界退出。
4. 前端模式开关和查证轨迹，验证刷新恢复、无障碍、失败状态及构建。
5. 小规模真实链路验收：同一输入分别运行两种模式，比较证据、耗时、调用量及质量；单独记录哪些原文来源已实际验证，不以 Fixture 结果宣称真实供应商验证通过。

测试重点包含无新证据、未知价格、工具超时、重复查询、非法工具/文档 ID、恶意新闻指令、未来信息、模型输出非法证据引用、并发预算、进程中断及旧数据兼容。Agent 模式是否有效以查证和引用闭环证明，不以调用次数证明。
