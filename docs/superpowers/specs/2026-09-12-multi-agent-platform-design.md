# SectorPulse 父子 Agent 平台设计

阅读入口：[旧版→新版功能迁移总说明](2026-09-13-feature-migration-map.md)。该文档逐项列出 30 项旧功能、5 类 Agent 角色、19 个拟定工具和 6 个 Skill 的去向；本文件仅解释架构原则。具体迁移边界与工具命名以迁移总说明为准，均不能当作已实现状态。

## 决策与范围

用户确认完全替换工作流/Agent 双模式；最终所有新分析任务只走父子 Agent 调度。历史记录保留原始模式字段，仅用于解释历史，不据此再启动旧执行器。框架必须实际复用本地 aidynamic-agent，而非另写循环后沿用名称。

源码来源：D:/work/project/agent，版本 0.3.0，Git 5abc18c906c806f9efa6956e6a4362870f4b1c6c。完整受版本控制的文件复制到 vendor/aidynamic-agent；不复制 .git、运行环境或未跟踪文件。原始源码先逐文件 SHA256 校验，再对必要缺陷做有测试覆盖的补丁。所有本地补丁记录在 LOCAL_CHANGES.md。上游声明 MIT，当前目录没有独立 LICENSE 文件；保留原声明，不自行编造版权人。

改造分阶段，最终才切换服务入口。过渡期旧入口继续工作，不能把“框架已引入”误称为“业务已迁移”。上一轮 YAML 提示词迁移保持不变。

## Agent、Tool、Skill 的职责

父 Agent（研究负责人）读用户目标及运行状态，决定委派、追问子任务、补查、审校和结束。父 Agent 不负责逐项算数或抓取网页。父子层级固定两层；归因角色可产生多个按板块隔离的实例，而不是多个永久常驻角色。

| 角色 | 自主决策 | 工具范围 | 可提交产物 |
| --- | --- | --- | --- |
| 数据与选题子 Agent | 是否补采、数据可用性、候选解释 | 行情采集、数据质量、评分、候选读取与提案 | 数据快照引用、候选提案 |
| 归因研究子 Agent | 检索改写、正文阅读、反证搜索、证据不足时结束 | 新闻检索、受限正文读取、行情对照、证据查询 | 板块归因卡 |
| 编辑写作子 Agent | 选材、大纲、表达、按反馈修订 | 读取归因卡、证据与草稿、提交草稿版本 | 完整草稿与章节证据映射 |
| 独立审校子 Agent | 核验主体、引用、因果强度及文稿问题 | 草稿/证据只读、提交审校报告 | 审校报告，不能改稿或批准 |

确定性 Tool 复用已有采集、规范化、去重、评分、领域校验与 Repository。LLM 不计算评分，不直接写 SQL，不自行构造已通过质量门禁的结果。候选提案只能引用运行中存在的板块，用户自选板块为硬约束，Agent 不可擅自替换。候选评分、排序规则不是 Skill 决定的可执行代码。

保留原候选确认的 3–12 个、唯一性、集合归属和版本校验；默认确认仅由创建任务时已授权的策略执行。Agent 提案不等于人工确认。人工编辑、批准、撤销和证据处置不开放给 Agent 工具。

Skill 是经过维护者审核的方法文档：数据缺口处置、板块选题、因果证据核查、新闻正文核验、分析写作、独立审校。通过框架 SkillManager/SkillTool 按需加载。角色身份、禁止行为和输出契约保存在 YAML 系统提示词；方法细则保存在 SKILL.md；权限、Schema 和预算由 Python 强制执行。Skill 资源只读、限定根目录、拒绝路径穿越，不暴露任意 shell 或文件写工具。不自动加载用户机器的 Codex skills。

## 调度不是固定工作流

框架 ParentAgent 的循环决定下一次调用 delegate、inspect_artifact、request_user_selection 或 finish。delegate 接收服务端注册角色名、任务说明、产物引用，不能接收任意权限/模型/系统提示词来提升子 Agent 能力。父 Agent 可以先补采再选题、并行研究不同板块、退回写作、针对审校发现重新查证。

程序验证的是合法性和前置材料，不替模型预排所有阶段。缺少已验证归因卡时不能提交完整草稿，缺少当前版本审校报告时不能宣告审校完成。这是业务不变量，不是硬编码调用顺序。

finish 必须通过 FinalizationPolicy 检查持久化产物，父 Agent 一句“完成”不代表运行成功。所有路径有明确终态：等待人工选择、等待人工审批、研究资料不足、超预算、失败、取消。自动审校完成与人工批准严格区分。

## 解耦与设计模式

- Adapter：FrameworkProviderAdapter 连接现有模型配置、鉴权和调用审计；BusinessToolAdapter 连接现有 application 服务。
- Factory + 明确角色配置：RoleAgentFactory 生成最小权限注册表、角色提示词和上下文；不使用巨型条件分支构造所有 Agent。
- Strategy：FinalizationPolicy、EvidencePolicy 分别判断完成及证据合法性，不把规则埋在提示词里。
- Repository：保存任务树、事件、上下文快照、产物索引；SQLite 和 PostgreSQL 提供同一接口。
- Observer/Hooks：记录启动、委派、工具调用和终态，驱动前端；业务状态以持久化记录为准，内存事件仅作通知。
- Decorator：给工具附加超时、幂等与审计；不为单纯转发堆叠无意义接口。

领域层不依赖框架类型。框架源码中不引入 sector_pulse。对接代码放 infrastructure/agents；调度用例放 application/orchestration；领域契约放 domain/orchestration；端口放 ports/orchestration。

## 知识与记忆

首期不建设向量知识库。现有行情快照、新闻、正文、证据、归因卡就是可查询的事实库；Skill/受控资源是方法库；任务树与产物引用是本次运行记忆。历史草稿只能用于明确标注的风格参考，不能作为事实或因果证据。新闻正文属于不可信数据，不得覆盖系统指令。

未来仅在有可维护的政策/公告/行业文档和检索评测集时增加检索端口实现。届时必须保留来源、发布日期、版本和撤销机制；不为“更像 Agent”增加向量数据库。

## 预算、权限与恢复

框架本地补丁先修复：toolsets 未生效、标签仅展示过滤而非执行授权、子 Agent token 未累计、超时仅轮次边界检查、子 Agent 配置继承不完整、子任务异常终态误报成功。子 Agent 已禁止 task，保留并增加回归；不要声称原版完全没有递归限制。

业务层增加父子共享预算：每次请求前预留输入估算与最大输出；返回后按实际 usage 结算；缺失 usage 时不标为零成本，保守保留预留；失败/重试也纳入调用限制。统一 deadline，取消父任务时传播至所有子任务。并发默认最多 2 个研究子任务，每个板块只允许一个活动任务；不是所有框架工具都并行执行。

可调起始上限：父 Agent 24 轮，单子任务 12 轮，整次运行 80 次模型请求、120 次工具调用、120000 token、1200 秒，修订最多 2 次。属于运行配置，不由模型修改；这是初始预算而非完成时延保证。正式真实调用前使用用户当前配置和明确额度授权验证。

这些限制不能替代已有人民币预算：必须继承 budget_cny_per_run，并明确价格/usage 未知时的保守策略，不能显示为确定的零成本。模型和工具审计绑定 run/task/attempt/role。当前 SharedBudget 已有 token/模型次数/deadline 和金额账本；金额配置生产接线、工具预算与完整审计是切换前必须补齐的缺口。

子任务收到不可变 run_id、task_id、scope 和 artifact refs。只返回概要和引用，不把整个父对话复制给所有子 Agent。任务以创建/运行/完成/失败/取消/等待记录，事件顺序号单调增长。工具写入采用 run/task/call 幂等键；未知结果先查询，不盲目重发。重启后不重复已提交产物；外部调用无法证明完成的任务标为中断，恢复时生成新 attempt。

幂等键具体采用 run/task/attempt/tool_call 并记录输入指纹；过期 attempt 不能提交产物。恢复前校验执行所有权，避免误中断其他进程的活动任务。业务产物与编排索引优先同库事务提交；快照持久化本身不代表业务写入完成。

## API、前端和兼容

保留现有运行、审核、新闻与板块页面，但创建表单不再提供执行模式开关。增加任务树、角色、当前工具、停止原因、预算及产物链接；不显示或存储模型隐藏思维链，只显示可审计的行动摘要和工具结果。历史固定阶段只为旧记录展示，新记录使用任务树。

数据库采用增量建表/迁移，保留旧数据，不批量重写旧状态。发布切换前必须完成 SQLite/PostgreSQL、fixture 端到端和前端回归；不提前删除旧入口导致系统不可运行。切换后旧模式参数给出明确迁移错误或规范化到唯一新入口（API 契约测试固定最终行为）。本设计选择拒绝显式传入旧模式参数，并给出新版接口提示。

## 验收

必须用确定性模拟模型跑出真实框架轨迹：父委派→子调用工具→发现资料不足→追加工具→提交归因卡→写作→审校退回→修订→当前版本审校完成。工具越权、伪造产物、重复执行、超预算、超时、取消、重启、用户自选约束均有失败测试。人工批准仍需用户操作。框架测试通过不等于业务端到端通过，验收分别记录。
