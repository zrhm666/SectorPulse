# Phase 4：审核与运营收口设计规格

日期：2026-08-23
状态：已自审，可实施
范围：审核工作台、调度管理、只读影子验收、全局反馈与最终响应式验收

## 1. 目标

Phase 4 把已经存在但分散在运行详情中的草稿、证据、治理和审批能力组织成一个日常可用的审核工作台，并完成调度与历史验收页面的运营化收口。

成功标准：

- 用户可从 `/review` 看到真实待审核队列，选择运行后阅读、修改、比较版本、处理证据并作出批准或退回决定。
- 每次正文修改都生成新版本，不覆盖旧版本；批准和退回前明确显示当前版本。
- 调度页可创建带明确时区的计划、查看状态摘要和响应式表格，并可手动触发。
- 影子验收继续暂停，历史记录完整只读，不出现创建、修改或伪造进度的入口。
- 成功、错误、确认和焦点恢复使用统一交互，不再使用 `alert()` 或 `console.error` 作为用户反馈。

## 2. 审核工作台 `/review`

### 2.1 三栏结构

- 左栏“审核队列”：从真实运行列表筛选具有草稿且已经结束的运行；状态筛选为待审核、已批准、全部。
- 中栏“文章与编辑”：展示当前版本、标题、导语、正文分节、结论、风险提示和版本选择；每次只编辑一个字段并保存为下一版本。
- 右栏“证据与合规”：展示治理状态、来源列表、证据决策和最终动作。

桌面宽屏保持三栏；1024px 下左栏变为顶部横向队列，中栏与右栏双栏；768px 下全部纵向排列。任意宽度都不能依赖水平滚动完成关键操作。

### 2.2 队列规则

- 默认选中第一条 `READY_FOR_HUMAN_REVIEW` 运行。
- 运行无草稿时不进入审核队列。
- 队列为空时说明如何先创建 Fixture 或 Live 分析，不生成样例条目。
- 切换运行时重新加载草稿、证据、治理、当前审批和审计记录；旧请求结果不能覆盖新选择。

### 2.3 编辑与版本

- 草稿 API 返回的 `versions` 是 append-only 历史；界面默认显示最新版本。
- 可选择旧版本只读查看；只有最新版本可编辑。
- 保存请求使用后端真实合同：`{base_version, operations:[{path, old_value_hash, value}]}`。
- 保存成功后刷新版本列表、选择新版本，并显示统一成功反馈。
- 409 冲突提示“草稿已有更新”，要求重新加载，不覆盖他人或其他标签页产生的新版本。

### 2.4 证据决策

- 每个来源可选择保留、降级、拒绝，并必须填写理由。
- 后端验证来源确实绑定当前草稿，持久化决策并返回受影响章节。
- 右栏显示当前草稿版本的历史决策；不修改新闻或引用原始记录。
- 不可用链接显示“无可访问链接”，不能使用 `href="#"`。

### 2.5 批准与退回

- “批准复制”要求治理通过，并通过确认对话框再次显示草稿版本。
- “退回修改”要求填写原因，通过确认后写入 append-only 审计事件 `RETURNED`；它不删除草稿，也不伪造新的 LLM 运行。
- 已批准版本可撤销批准；导出只在当前版本已批准时出现。
- 切换草稿版本后必须重新读取该版本对应的审批状态。

## 3. 后端最小合同

### 3.1 草稿补丁

前端改为后端既有 `operations` 数组合同，不修改后端模型。

### 3.2 证据决策

新增：

- `GET /api/runs/{run_id}/drafts/{draft_id}/evidence-decisions`
- `POST /api/runs/{run_id}/drafts/{draft_id}/evidence-decisions`

POST 输入：`source_id`、`decision`、`reason`。返回决策编号、草稿版本、受影响章节和创建时间。

### 3.3 退回修改

新增：

- `POST /api/runs/{run_id}/drafts/{draft_id}/return`

输入 `reason`，后端读取最新版本并追加 `RETURNED` 审计事件。返回草稿编号、版本、状态和操作者。

## 4. 调度管理 `/schedules`

- 顶部摘要：计划总数、启用数、盘中数、盘后数。
- 创建表单字段：名称、模式、时区、本地执行时间、交易日规则、启用状态。
- 时区使用显式 IANA 选项，默认 `Asia/Shanghai`；本地时间使用 `type="time"`。
- 表格列：状态、名称、模式、时区与本地时间、交易日、下次触发、操作。
- 创建和触发均有忙碌、成功和错误反馈；触发成功进入任务运行详情。

## 5. 只读影子验收 `/shadow-acceptance`

- 始终显示“已暂停”说明，明确不会新增交易日。
- 摘要显示已记录交易日、通过、失败、阻塞和剩余目标数；“剩余”只描述历史目标差额，不表达正在执行。
- 历史记录使用响应式表格，列出日期、模式、状态、运行编号、记录时间。
- 页面不调用 POST/PATCH，不提供编辑、补录或重新开始按钮。

## 6. 全局反馈与确认

- `FeedbackProvider` 放在 AppShell，暴露 `success`、`error`，通知区域使用 `aria-live="polite"`。
- 通知 5 秒后自动消失，悬停不承担唯一可读方式，并提供关闭按钮。
- `ConfirmDialog` 使用原生 `<dialog>`，打开后聚焦取消按钮，关闭后焦点回到触发按钮；Escape 等价于取消。
- 破坏性或不可逆语义动作使用危险按钮；批准属于受保护动作但不是危险动作。
- `prefers-reduced-motion` 下取消位移动画，保留即时状态变化。

## 7. 安全与文案

- 不显示 API Key、Base URL、原始异常栈、内部输入 JSON。
- 后端错误按冲突、治理未通过、来源不属于草稿、服务不可用分类为安全中文提示。
- 证据决策与退回原因不得为空；前后端都校验。
- 外部证据链接使用 `target="_blank"` 和 `rel="noreferrer"`。

## 8. 验收

- 自动化覆盖队列空态、运行切换、版本只读/可编辑、补丁合同、冲突、证据决策、批准确认、退回确认、调度创建/触发、影子只读。
- Fixture 浏览器流程：创建运行、进入审核队列、保存一个正文修改产生新版本、记录证据决定、退回、重新批准并验证导出入口。
- 空数据库和 Fixture 数据库均检查。
- 视口：1440、1024、768、390px；无水平溢出，键盘焦点可见，移动导航可用。

## 9. 明确不做

- 不新增多人协作、角色权限、富文本编辑器或自动保存。
- 不恢复影子验收执行。
- 不新增调度编辑/删除；本阶段只创建、查看和手动触发，避免无后端合同的伪管理。
- 不自动调用真实 LLM 或真实行情完成验收。

## 10. 自审结论

规格覆盖总计划 Phase 4 的审核、版本、调度、影子只读、全局反馈和最终浏览器验收。新增后端范围仅限证据决策与退回审计，既有草稿 append-only 结构保持不变，没有占位需求或未定义接口。
