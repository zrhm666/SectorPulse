# Phase 4：个人服务器与插件演进设计

## 目标

在单机 SQLite 版本稳定后，为个人服务器部署提供可重复启动的容器配置、外部数据库迁移路径和可选 Provider 插件边界。默认仍使用 SQLite，不因部署能力引入不必要的基础设施。

## 核心决策

- Docker Compose 只编排 Web 服务和可选 PostgreSQL，不自动启用外部对象存储。
- 数据库通过 `DATABASE_URL` 配置；SQLite 是默认和本地开发路径。
- Provider 插件实现显式注册接口，不允许插件直接访问 Web 层或修改事实账本。
- 密钥只通过环境变量或容器 Secret 注入，不写入镜像、日志和数据库。
- 继续保持草稿、复制、导出和人工发布边界。

## 退出条件

- 空目录可启动健康检查。
- SQLite 配置行为不回归。
- PostgreSQL 迁移路径有明确阻断或通过证据。
- 插件加载失败时服务仍可启动，并返回可解释的 Provider 不可用状态。
