# 真实采集数据可见性设计

## 1. 目标

让用户在数据运行详情页直接回答以下问题：

- 本次运行实际访问了哪些 Provider；
- 每个 Provider 返回了多少条数据、状态如何、何时采集；
- 行情来源实际提供了哪些字段，哪些字段没有返回；
- 新闻来源实际取得了哪些标题、摘要、媒体、发布时间和原文链接；
- 哪些数据只是采集记录，哪些已经进入候选筛选或证据关联。

页面不得把缺失值显示为真实的 `0`，也不得把系统规范化记录描述成供应商的完整原始响应。

## 2. 已确认的根因

当前运行 `5ea4c072-cae8-4c54-bedf-01832d198a5e` 的 PostgreSQL 记录显示：

- 同花顺行业和概念快照分别保存了 90、375 个板块；该接口实际只提供板块代码和名称，涨跌幅、换手率、上涨/下跌家数和领涨股均未返回；
- 领域映射为了支持候选计算，把缺失涨跌幅回退成了 `0`，页面又无条件追加 `%`，因此产生了“真实涨跌幅为 0%”的错误观感；
- 新闻查询审计已经保存：东方财富 24 次查询、240 条结果，财联社 1 次查询、15 条结果；
- `news_source_runs` 没有保存本次执行汇总，页面也没有读取 `news_queries` 的接口；
- 新闻文档已保存标题、摘要、媒体、时间和链接，但当前页面只显示通过 `sector_event_links` 关联后的证据，无法明确区分“全部采集记录”和“进入证据链的记录”；
- 当前表结构没有 run/query 到 document 的完整关联，历史运行无法可靠还原每一次查询取得的全部新闻文档。

## 3. 方案比较

### 方案 A：只增加 Provider 数量卡片

在现有页面顶部显示 Provider、数量和状态。改动较小，但用户仍无法查看具体新闻记录，也无法理解 `0%` 是否是真实值。

### 方案 B：采集概览 + 规范化记录浏览器（采用）

顶部固定展示本次采集概览；行情页明确展示字段覆盖度；新增“新闻记录”页展示未经 LLM 加工的本次新闻；保留“新闻证据”页表示关联和去重后的下游结果。该方案能够同时表达来源、数量、具体内容和处理层级，且不保存新闻完整正文。

### 方案 C：完整保存供应商原始响应

把 DataFrame/HTML/JSON 原文作为 artifact 保存并提供下载。审计能力最强，但会增加供应商许可、敏感内容、存储量和结构漂移风险，不适合当前本地自托管阶段。

## 4. 页面信息架构

### 4.1 “本次实际获取”概览

时间线之后、数据标签之前固定显示来源卡片：

- 行业行情：Provider、状态、记录数、观测时间、采集时间、实际字段；
- 概念行情：同上；
- 每个新闻 Provider：查询数、成功/部分成功/失败数、结果数、重试数和安全错误码；
- 汇总：规范化新闻文档数、去重事件数、已关联证据数。

卡片使用明确的层级标签：`Provider 返回`、`规范化保存`、`进入证据链`。不能用一个“新闻数”混合三种计数。

### 4.2 行情记录

继续使用行业/概念切换和服务端分页，但增加字段覆盖提示。例如：

> 同花顺本次仅返回板块代码、板块名称；涨跌幅、换手率等指标未返回。

表格依据快照的 `available_fields` 渲染。未返回字段显示“未返回”，真实数值零才显示 `0%`。来源版本、分类版本、采集时间和原始响应 SHA-256 可在来源详情中查看。

### 4.3 新闻记录（新增标签）

展示本次运行取得并规范化保存、但尚未经过 LLM 写作的新闻记录：

- 标题；
- Provider 和媒体；
- 发布时间、Provider 观测时间和系统采集时间；
- 最多 500 字的已有摘要；
- 来源等级；
- 原文链接；
- 对应查询类型和查询状态。

支持按 Provider、查询状态筛选和服务端分页。页面不展示或保存新闻完整正文。

### 4.4 新闻证据

保留现有“新闻证据”标签，并增加说明：此处只展示完成去重、板块映射并进入证据链的记录。事件需要展示关联板块名称、命中实体、映射置信度和映射原因，使用户能够从新闻追溯到候选板块。

## 5. 数据模型与持久化

### 5.1 行情字段覆盖

`SectorUniverseSnapshot` 增加向后兼容的可选元数据：

- `available_fields`：Provider 本次实际提供的规范字段集合；
- `raw_artifact_sha256`：供应商响应计算出的哈希，不保存原始响应内容。

AKShare/同花顺 mapper 根据原始行的列名计算字段覆盖度，不依据数值是否为零猜测。旧快照缺少该元数据时，页面显示“历史快照未记录字段覆盖度”；对已知同花顺名称列表快照可保守地只声明代码和名称，不把旧的回退零声明为真实值。

### 5.2 新闻运行关联

新增迁移 `014_real_data_visibility.sql`，建立 `news_query_documents`：

- `run_id`；
- `query_id`；
- `document_id`；
- 主键为三者组合；
- 外键分别指向 `news_queries(run_id, query_id)` 和 `news_documents(document_id)`。

新闻查询执行结束后，在保存查询审计的同一持久化边界写入 query-document 关联。`news_source_runs` 同时保存由执行结果聚合出的来源指标。

历史运行没有 query-document 关联时，只能返回现有的已关联证据文档，并在 API 和页面标记 `coverage=LINKED_ONLY`，不得声称这是本次全部新闻。

## 6. 后端接口

### 6.1 采集概览

`GET /api/data-runs/{run_id}/acquisition`

返回：

- `market_sources`：两类快照及字段覆盖；
- `news_sources`：按来源聚合的查询和结果状态；
- `counts`：规范化文档、事件、证据关联数量；
- `coverage`：`COMPLETE` 或 `LINKED_ONLY`；
- `coverage_notice`：历史数据不完整时的中文说明。

### 6.2 新闻记录

`GET /api/data-runs/{run_id}/news-records?source_id=&status=&offset=0&limit=20`

返回本次运行范围内的分页新闻记录、查询元数据和覆盖范围。`limit` 范围为 1–100。无关联的历史运行不得回退到全局 `news_documents`，避免混入其他运行的数据。

### 6.3 行情接口增强

现有 `/market` 响应增加 `available_fields`、`raw_artifact_sha256` 和 `coverage_notice`。行业/概念记录仍由现有接口分页返回，不新增重复行情接口。

## 7. 错误与安全边界

- Provider 失败时展示安全错误码，不返回代理地址、请求头、API Key 或完整第三方异常；
- 某个来源查询失败不隐藏其他来源已经取得的数据；
- 新旧运行的覆盖范围必须显式标注；
- 原文链接使用新窗口安全属性；
- 不触发新的 Provider 请求或 LLM 调用，所有详情接口只读数据库；
- 不展示新闻完整正文，不提供原始响应下载。

## 8. 测试与验收

- mapper 测试覆盖“字段缺失”和“真实零值”的区别；
- SQLite/PostgreSQL 仓储测试覆盖 query-document 关联和来源指标；
- 查询层测试覆盖完整运行、历史 `LINKED_ONLY`、筛选和分页；
- API 测试覆盖 acquisition、news-records、404 和参数 422；
- 前端测试覆盖来源卡片、字段未返回、真实零值、新闻分页、历史覆盖提示和独立失败状态；
- 完整后端非 live 回归、完整前端测试和生产构建必须通过；
- 使用现有 PostgreSQL 运行做只读页面验收，不触发真实 LLM。

## 9. 非目标

- 不保存或下载供应商完整原始响应；
- 不保存新闻完整正文；
- 不在本阶段增加行情图表、导出或高级搜索；
- 不改变候选和证据算法；
- 不自动重新采集历史运行。
