# 数据运行工作台完善设计

## 1. 目标

将真实数据运行详情页从单一进度摘要补全为可持续操作、可复盘的数据工作台。用户无需返回“新建分析”，即可看到当前运行已经采集的行情、候选板块、新闻证据和质量报告，并能继续生成或查看分析稿、按原参数重新采集。

## 2. 现状与根因

- 页面只调用数据运行详情和候选板块两个接口。
- 行情快照、新闻事件、新闻文档、证据包和板块映射虽已持久化，但没有对应 Web 查询接口。
- “生成分析稿”仅在 `READY_FOR_ATTRIBUTION` 时临时显示，成功后立即跳转，数据页没有保存后续内容运行的可见入口。
- 数据阶段时间线把所有节点同时标成“进行中”，没有表达已完成、当前、等待、失败或中断。
- 失败、中断或降级运行缺少按原参数重试入口。

## 3. 页面信息架构

### 3.1 顶部摘要

保留运行状态、场景和候选板块数，并补充 cutoff、开始时间、结束时间，以及行业/概念快照数量。运行尚未产生某项数据时显示“尚未产生”，不得用 0 冒充采集成功。

### 3.2 固定下一步操作区

操作区始终存在，并按状态显示一种明确动作：

- 采集中：显示当前阶段与“等待数据就绪”，主按钮禁用。
- `READY_FOR_ATTRIBUTION` 且无内容运行：显示“生成分析稿”。
- 已存在内容运行：显示其状态和“查看生成进度”或“查看分析稿”，生成成功后留在当前数据页。
- `DEGRADED`、`BLOCKED`、`FAILED`、`CANCELLED`、`INTERRUPTED`：解释当前不可继续生成的原因，并提供“按原参数重新采集”。

内容运行继续复用相同 `run_id`。查询是否存在 `phase1b_runs` 记录即可建立关联，不新增映射表。

### 3.3 数据标签

工作台包含四个标签：

1. **行情板块**：行业/概念来源、观测时间、采集时间、板块总数；表格显示板块名称、涨跌幅、换手率、上涨/下跌家数、领涨股和领涨股涨幅。支持类型筛选和服务端分页，默认每页 20 条。
2. **候选板块**：排名、板块名称、板块类型、综合评分和入选理由。名称来自对应行情快照，不只展示供应商 ID。
3. **新闻证据**：按新闻事件展示标题、首发时间、去重原因；展开后展示媒体、摘要、证据等级、引用链接，以及与哪些候选板块关联。只展示本次运行通过 `sector_event_links` 关联的数据。
4. **质量报告**：市场与新闻来源状态、cutoff 越界数、重复文档数、降级原因和运行错误码。

部分数据已经产生时立即展示，不要求运行先进入终态。

## 4. 阶段状态

数据阶段固定为：行情采集、预候选排序、新闻采集、证据构建、归因就绪。

- 当前运行状态对应节点显示“进行中”。
- 当前节点之前显示“已完成”。
- 当前节点之后显示“等待中”。
- `READY_FOR_ATTRIBUTION` 时全部完成。
- 失败、中断或取消时，已知完成节点保留完成状态，当前节点显示“失败”“已中断”或“已取消”，后续节点显示“未执行”。

刷新和历史访问以持久化 `real_data_runs.status` 为准，不依赖进程内 SSE。

## 5. 后端查询接口

### 5.1 行情

`GET /api/data-runs/{run_id}/market?kind=INDUSTRY&offset=0&limit=20`

返回：

- 两类快照摘要；
- 当前筛选后的分页板块；
- `total`、`offset`、`limit`；
- Provider、分类版本、来源版本、观测时间和采集时间。

`kind` 可为 `INDUSTRY` 或 `CONCEPT`，`limit` 范围为 1–100。

### 5.2 新闻证据

`GET /api/data-runs/{run_id}/evidence`

查询 `sector_event_links`、`news_events`、`news_event_documents` 和 `news_documents`，按本次运行聚合事件、文档和关联板块。不得返回新闻完整正文或未关联到本次运行的全局新闻。

### 5.3 质量报告

`GET /api/data-runs/{run_id}/quality`

返回市场/新闻质量、cutoff 越界数、重复文档数、降级原因和错误码。

### 5.4 内容运行关联

`GET /api/data-runs/{run_id}/content-run`

没有对应 Phase 1B 运行时返回 `null`；存在时返回运行 ID、状态、草稿 ID和是否可查看草稿。

### 5.5 重试

`POST /api/data-runs/{run_id}/retry`

只允许已结束、失败、中断、取消或明确降级的运行。读取原请求参数和原 Provider，创建一个新运行并返回新 `run_id`。运行中的任务和 `READY_FOR_ATTRIBUTION` 不允许重试，返回 409。

为保证重启后可重试，`real_data_runs` 必须持久化 Provider。新增迁移字段 `provider TEXT NOT NULL DEFAULT 'live'`，SQLite 和 PostgreSQL 仓储同步读写。

## 6. 错误与空状态

- 每个标签独立加载；一个接口失败不隐藏其他已成功数据。
- 运行不存在返回 404；参数无效返回 422；状态冲突返回 409。
- 尚无行情、候选或新闻时说明当前处于哪个阶段，不笼统显示“没有数据”。
- 引用链接只在合法 URL 存在时可点击，并使用新窗口安全属性。
- 页面不展示原始堆栈、密钥或 Provider 内部异常。

## 7. 测试

- SQLite 与 PostgreSQL 仓储测试覆盖 Provider 迁移和重试所需请求恢复。
- 查询测试覆盖行情分页、名称补全、新闻事件/文档/板块聚合、质量计数和内容运行关联。
- API 集成测试覆盖五个新增接口、404/409/422 语义。
- 前端组件测试覆盖运行中、就绪、已生成、失败/中断重试和四个数据标签。
- 前端生产构建及后端完整非 live 回归必须通过。

## 8. 非目标

- 不自动触发 LLM，不自动发布文章。
- 不保存或展示新闻完整正文。
- 不把未关联本次运行的新闻混入证据页。
- 不为行情表加入复杂图表、导出或自定义列。
- 不在本次实现完整 SSE 事件持久化。
