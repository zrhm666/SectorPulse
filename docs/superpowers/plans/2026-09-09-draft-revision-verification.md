# 草稿主体与修订：本批验收说明

## 已实现

- 行情快照名称写入归因上下文；模型不能替换可信名称，归因失败降级也保留名称。
- 旧 JSON 无名称仍可读；暂时无法恢复名称时，生成输入使用“行业/概念板块〔ID〕”，不猜名字。
- 写作章节与运行、大纲板块唯一绑定；标题和正文首句必须明确主体。
- 内容中的已知审核标记转为审核问题，不再通过追加“（已复核）”制造修订版本。
- `revision` 路由真实生成结构化修改集；范围、来源、证据等级、主体、系统标记和禁止用语校验后才保存新版本。
- 无变化、失败或不合法修改不递增版本；错误保存在审核问题中，不拼入正文。
- 每个新版本重新审核，拒绝草稿/版本错配报告；最多两轮修订。自动审核通过仍不等于人工批准。
- Web 外部调用日志回调不再导致内部成本统计归零；预算用尽后不发起后续模型请求。

## v1、v2、v3 的含义

这些是内容版本，不是审核次数。真实修订成功才创建下一版本；审核失败或没有实际改动不会制造新版本。历史上旧代码生成的版本不会自动重写，也不会自动去掉旧正文标记。

## 续批：名称恢复与只读预览

Web 重试现可从原运行快照补齐缺失名称，原运行输入保持不变。类型错误、重复 ID 或无法唯一匹配的名称不恢复。预览模块列出字段前后值和无法解析章节，无实际变化时不提议新版本。

只读命令（替换明确的目标参数）：

```powershell
.venv/Scripts/python.exe scripts/repair_draft_identity.py --sqlite data/sector-pulse.db --run-id <运行UUID> --draft-id <草稿UUID> --expected-version <当前版本>
```

PostgreSQL：在当前终端设置 `SECTOR_PULSE_DATABASE_URL`，不传 `--sqlite`。工具不会自动加载 .env，不打印连接异常详情。只有确认章节尾部标记由旧系统追加时，才传 `--confirmed-system-markers` 生成清理建议；正文中间正常引用不会删除。

命令默认 dry-run；`--apply` 必须同时提供明确目标、`--expected-preview-hash` 和 `--actor`，并在版本冲突时拒绝写入。SQLite/PostgreSQL 均验证失败审计回滚、并发冲突、旧批准不继承。未对用户业务草稿运行预览，因为尚无明确目标 ID。
