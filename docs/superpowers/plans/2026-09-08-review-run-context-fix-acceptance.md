# 审核来源关联与历史阶段显示修复

## 实际问题

用户提供的运行 75c11bc0 在只读接口检查中为 UNREVIEWED，有一个草稿版本，
运行详情记录12个板块，自动审核结论为空。不能据此判定所有步骤未执行，
也不能直接将自动审核补成通过。

历史终态进入页面后 useRunSSE 不订阅事件；ProgressBus 仅保留进程内有界事件。
阶段条原先把 done 且未见事件等同于 skipped，这是错误显示的直接原因。

审核工作台原先只突出短 ID，没有来源运行摘要和反向入口；指定运行不在最近
50条列表时会退回选择另一篇草稿，URL 改变也可能仍保留旧选择。

## 已实施

- 审核页固定来源摘要：时间、来源、内容生成场景、完整运行 ID、查看分析运行。
- 审核队列显示运行时间、短 ID 和中文数据来源；保持原有视觉规范及独立滚动。
- 选中运行同步到 URL；支持指定历史运行不在最近列表时按 ID 补查。
- 指定运行不可用时明确报错并提供重试/运行历史入口，不静默打开其他草稿。
- 有草稿且非运行中的内容详情均提供进入审核工作台入口。
- 根据已有草稿、归因卡片、审核结论确认对应阶段；其余历史阶段显示未记录。
- 明确区分自动审核完成、审核通过和人工批准。
- 来源跳转拦截未保存/冲突修改；保留现有编辑、治理和批准保护。
- 分离页面卸载与队列刷新清理逻辑，避免 URL 同步中止尚未返回的草稿请求。

## 边界

仅前端代码及测试变化，复用现有 API，不修改数据库表、业务记录或后端业务逻辑。
不伪造缺失的自动审核、编辑阶段或历史进度事件；没有运行真实 LLM/行情采集。
本轮修复未将进度总线改为永久事件存储。
